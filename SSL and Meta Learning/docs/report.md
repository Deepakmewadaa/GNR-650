## 3. Model architecture and rationale

- **Encoder**: ResNet-18-style CNN written from scratch (`models/resnet.py`): BasicBlocks [2,2,2,2], widths [w,2w,4w,embed_dim] (w=64, embed_dim=512 by default), BatchNorm, global average pooling → 512-d feature. ## 4. Component 1 — self-supervised feature learning (SimCLR)

SimCLR (Chen et al., 2020): two augmented views of each image, encoder + MLP projector, NT-Xent loss over the 2N views of a batch (positives = the other view, 2N−2 negatives). Augmentations are implemented from scratch as batched GPU tensor ops (`ssl_methods/augment.py`): random-resized-crop (scale 0.08–1) + flip as one affine `grid_sample`, colour jitter (0.4, 0.4, 0.4, 0.1; p=0.8), grayscale (p=0.2), Gaussian blur (p=0.5), optional solarisation. Optimiser LARS (lr 0.3×B/256, wd 1e-6, warmup 10 epochs + cosine), bf16 autocast, temperature 0.2. The number of epochs is set automatically from the measured epoch time and the time budget.

## 5. Component 2 — linear probing on noisy labels

The encoder is frozen (eval-mode BN). Features: clean view with horizontal-flip TTA plus 8 mildly augmented views (crop 0.35–1 + flip) used as feature-level data augmentation. The head is trained with Adam (L2 weight decay chosen from a grid with CE on the seed-0 split), 100 epochs, cosine LR. Methods compared (each over 3 seeds; each seed = its own stratified 80/20 split):

- losses: CE, label smoothing (ε=0.1), symmetric CE (α=0.1, β=1), generalised CE (q=0.7), soft bootstrapping (β=0.8);
- sample selection, then CE/GCE on the kept samples: kNN label consensus, class-prototype consistency, small-loss selection with the estimated noise rate, confident learning (confident-joint off-diagonal), and a consensus of ≥2 of {kNN, prototype, CL}. A per-class floor keeps ≥30 % of every class.

Validation labels are themselves noisy, so absolute accuracies are pessimistic; under roughly symmetric noise the noisy-label accuracy is a monotone function of the clean accuracy, so the method ranking remains valid.

## 6. Component 3 — unknown-class detection

Scores (higher = known): MSP, max-logit, energy, kNN distance (k-th neighbour, L2-normalised features), Mahalanobis (class means + shared covariance with 10 % shrinkage, normalised features), cosine-to-prototype, **knn_ratio** (mean top-k similarity to the labelled bank minus mean top-k similarity to the unseen unlabelled calibration holdout — a kNN density ratio p_known/p_pool: unknown-class images have same-class neighbours in the pool but not among the labelled images), and a z-score ensemble whose normalisation statistics come from known calibration data only.

**Score selection — leave-class-out protocol** (no test data): 5 folds with fixed seeds; each holds out 20 % of the labelled classes as pseudo-unknown, fits the selected probe method + OOD statistics on the remaining classes' training split and scores their validation split and all held-out-class images; the score with the best mean balanced open-set accuracy ½·(known acc. incl. rejections) + ½·(unknown recall) is selected.

**Threshold — expected (K+1)-accuracy on the unseen pool.** The calibration holdout is a random, never-seen part of the unlabelled pool, i.e. distributed like the test set: a mixture of known-class images (fraction π) and unknown-class images. Using known scores from 5-fold cross-fitting and holdout scores from the same fold models: π ≈ P_pool(s ≥ t)/P_known(s ≥ t) in the upper tail of the known scores (mixture-proportion estimation); estimated unknown recall UR(t) = (P_pool(s<t) − π·P_known(s<t))/(1−π); estimated known accuracy KA(t) from cross-fitted predictions (corrected for label noise); the threshold maximises π·KA + (1−π)·UR. It is stored as a percentile of the known calibration scores. (Validated on synthetic data with ground truth: estimated (K+1)-accuracy 0.813 vs. measured 0.800; it beat the balanced LCO threshold 0.800 vs 0.763.)

**Failed design decisions observed during development (real, from smoke tests on synthetic data):**

1. *Linear-probe learning rate too low.* With lr = 1e-3 and ~100 steps the zero-initialised head barely moved (mean |W| ≈ 0.008), so CE, label smoothing, SCE, GCE and bootstrapping produced **identical** predictions — the comparison of noise-robust losses was meaningless. Raising the lr to 1e-2 (with weight decay chosen on validation) let the heads converge and the losses separate. Lesson: verify that a 'method comparison' actually changes the model before trusting a tie.
2. *FLOP counter silently switched the encoder to training mode.* Wrapping the encoder in a fresh `nn.Sequential` (which defaults to train mode) and restoring that mode afterwards put BatchNorm into batch-statistics mode; the export self-test caught 7/12 predictions differing between `test.py` and the in-process model. Fixed by restoring every sub-module's own mode. Lesson: always self-test the exact grader code path.

The deliberately weak SSL setting (minimal augmentation) in the ablation table is the planned real-data failed experiment: without strong crops/colour distortion the contrastive task can be solved from low-level colour statistics, which is expected to give worse kNN/probe accuracy.

## 8. Limitations (honest)

- All validation labels are noisy; reported accuracies are noisy-label accuracies (pessimistic, ranking-valid).
- The threshold assumes the hidden test set is distributed like the unlabelled pool (the IDs suggest the test images come from the same 50k-image pool). If the test known/unknown mix differs, the operating point is suboptimal; `--set ood.threshold_mode=lco` gives the mix-independent balanced point instead.
- The known-fraction estimate is a statistical estimate (about ±0.05 at our sample sizes).
- SSL is trained on ~21k instead of 25k images (labelled copies + calibration holdout are excluded) — a deliberate trade of a little representation quality for unbiased calibration.
- Held-out-class images also carry label noise (some are really known-class images), which blurs the OOD estimates.
- Single-scale centre-crop preprocessing discards image borders of non-square photos.
- Compute budget (~6 GPU-hours) limits SSL epochs; longer training would likely improve all components.
